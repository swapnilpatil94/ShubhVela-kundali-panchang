# Build kit: how to build Parivaar Panchang with Claude Code (Fable + Opus)

> **Start here:** `MASTER.md` is the single source of truth, covering every spec, ops step, routing rule and prompt. `MASTER_PROMPT.md` holds the copy-paste prompts. Copy this whole folder, including the hidden `.claude/`, into your new repo. The `docs/*.md` files are the same content split by topic, for reference.

## Setup (once)
1. Create an empty Git repo.
2. Copy into it:
   - `CLAUDE.md` → repo root.
   - `docs/` → `docs/`.
3. Open the repo in Claude Code.
4. Run milestones from `docs/PROMPTS.md` **one per session**, in order, starting with M00. Between milestones run `/clear` and commit.

## Model routing (cost vs. correctness)
Prices are per million tokens, input / output.

| Work | Model | Effort | Why |
|---|---|---|---|
| Engine (M01–M04), secure data (M06), release audit (M18), AI proxy (M27), policy review in M15 | **Fable 5.2** ($8/$40) | high (xhigh for M04) | Hardest correctness and security work, where a bug costs user trust |
| All feature/UI milestones | **Opus 5.5** ($4/$20) | **high** (set it explicitly; the default is medium) | Strong coding at half Fable's price |
| Bhakti screens, localization plumbing, small fixes | **Sonnet 5.5** ($2/$10) | medium–high | Simple, well-specified tasks |
| Bulk translation (script calls the API) | **Haiku 5.5** ($0.10/$0.50) via Batch (−50%) | low | Cheap bulk text. Native human review afterwards |

## Token-saving rules (already in CLAUDE.md)
- **Keep each session to one task.** Each milestone names the exact doc sections to read, so the model doesn't load everything.
- **Specs carry acceptance tests.** The model verifies its own work against those tests, so you don't spend tokens re-explaining.
- **Golden data replaces long explanations.** `engine-golden/*.json`, generated by `tools/oracle` with Skyfield + JPL DE440, is the ground truth.
- **Ambiguity is logged, not asked.** It goes into `docs/DECISIONS.md` instead of a back-and-forth.
- **Parallelize safely.** After M07, feature milestones that touch different modules (M09, M10, M12, M13) can run in parallel git worktrees.
