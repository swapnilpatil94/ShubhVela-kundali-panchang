# M05 Geo and timezones (spec)

## 1 Goal
Offline place search (seed now, GeoNames FTS DB when the owner supplies data) and a resolver that turns (IANA zone + longitude + overlay key) into the UTC offset the engine takes, including DST gaps/overlaps, historical South Asian overlays, LMT and manual override.
Implements MASTER Part 3 §9 (and §8 boundary cases: DST US/UK/AU, dateline, pre-1955 Mumbai/Kolkata, 1941–45), Part 4 module graph (`:core:geo`, `:core:model`), Part 5 Permissions/STORAGE, Part 12 M05. Routing (Part 11): every task is BUILD (implementer); no CRIT part.
**In scope:** contract types, name normaliser (Kotlin + Python twin), seed TSV + in-memory search + nearest place, `rules/tz_overlay.json`, `java.time` resolver, tz golden oracle, manual-offset UI model (no Compose), GeoNames DB generator (tested on synthetic input), SQLite store adapter. **Out:** location fetch and its rationale UI (M07), onboarding/search screen (M07), persisting places in profiles (M06/M10), caching panchang per place (M08), device-run instrumented tests (TODO(owner)).

## 3 Public API (package `app.parivaar.panchang.core.model.geo` unless noted; `Instant` = `kotlin.time.Instant`)
```kotlin
data class GeoPlace(val id: Long, val name: String, val admin1: String?, val countryCode: String, val latDeg: Double, val lonDeg: Double,
                    val elevationM: Double?, val population: Long, val zoneId: String, val overlayKey: String?)
data class PlaceHit(val place: GeoPlace, val matchedName: String, val tier: Int)
data class TzContext(val zoneId: String, val lonDeg: Double, val overlayKey: String?)   // GeoPlace.tzContext() extension
@JvmInline value class ManualOffset(val seconds: Int)          // init: require(seconds in -43_200..50_400) (message has no value)
enum class OffsetSource { IANA, OVERLAY, LMT, MANUAL }
enum class OffsetFlag { DST, GAP_SHIFTED, AMBIGUOUS, NONEXISTENT_DATE, HISTORICAL_VERIFY, PRE_STANDARD_LMT, NO_OVERLAY_DATA }
enum class AmbiguityChoice { EARLIER, LATER }
data class ResolvedOffset(val offsetSeconds: Int, val source: OffsetSource, val flags: Set<OffsetFlag>, val overlayId: String?)
sealed interface CivilDayOffset { data class Valid(val offset: ResolvedOffset) : CivilDayOffset; data object Nonexistent : CivilDayOffset }
data class LocalResolution(val instant: Instant, val offset: ResolvedOffset, val alternative: Instant?)  // alternative = other instant if AMBIGUOUS
// package app.parivaar.panchang.core.geo
interface PlaceSearch { fun search(query: String, limit: Int = 20): List<PlaceHit>; fun nearest(latDeg: Double, lonDeg: Double, maxKm: Double = 100.0): GeoPlace? }
interface OffsetResolver {
  fun offsetAt(instant: Instant, ctx: TzContext, manual: ManualOffset? = null): ResolvedOffset
  fun civilDayOffset(date: LocalDate, ctx: TzContext, manual: ManualOffset? = null): CivilDayOffset   // feeds PanchangCalculator.day(date, offset, ...)
  fun localToInstant(local: LocalDateTime, ctx: TzContext, choice: AmbiguityChoice = AmbiguityChoice.EARLIER, manual: ManualOffset? = null): LocalResolution
}
class JavaTimeOffsetResolver(overlay: TzOverlay) : OffsetResolver { internal fun ianaOffsetAt(zoneId: String, instant: Instant): Int }
class SeedPlaceStore(tsv: String, overlayKeys: Set<String>) : PlaceSearch;  class SqlitePlaceStore(dbFile: java.io.File) : PlaceSearch
object PlaceStores { fun create(context: android.content.Context): PlaceSearch }   // SqlitePlaceStore iff asset geo/places.db exists, else SeedPlaceStore
fun GeoPlace.toEnginePlace(): Place = Place(latDeg, lonDeg, elevationM ?: 0.0)
```
Unknown zone id: `offsetAt`/`civilDayOffset`/`localToInstant` throw `UnknownZoneException` (message without the id). All functions pure and thread-safe; no I/O after construction.

## 4 Rules
**4.1 NameKey (Kotlin `java.text.Normalizer`, Python `unicodedata`, identical):** NFKD → delete U+0300–U+036F, U+200C, U+200D → lowercase (`Locale.ROOT` / `str.lower`) → every char that is not a letter (L*), mark (M*) or digit (Nd) becomes a space → collapse runs of spaces, trim. Tokens = split on space. Query with < 2 code points (spaces excluded) → empty result.
**4.2 Search:** keys of a place = NameKey of `name` and of every alt name (display text kept). Tier per key: 0 key == q; 1 key startsWith q; 2 every q token is a prefix of a distinct key token; else no match. Per place keep the best (tier, key). Sort by (tier asc, population desc, matchedName key asc, id asc); `limit` clamped to 1..50. `matchedName` = the original alt/primary string that matched.
**4.3 Nearest:** haversine, R = 6371.0088 km; linear scan (seed) or lat/lon box query (SQLite: box ±maxKm/111.0° lat, ±maxKm/(111.0·max(cos lat, 0.01))° lon, split at ±180°) then exact haversine; ties by id; none within maxKm → null. Input coordinates are used once in memory, never stored, logged or returned.
**4.4 Offset function f(instant, ctx)** (first match wins): (1) `manual` → MANUAL; (2) overlay entry with `key == ctx.overlayKey` and `fromUtc ≤ t < untilUtc`: offset non-null → OVERLAY (+`overlayId`), null → fall through adding NO_OVERLAY_DATA; (3) t < 1900-01-01T00:00:00Z, or t < `ZoneRules.transitions.first().instant` (zone still on reference-city LMT) → LMT = `Math.round(lonDeg * 240.0).toInt()` s, flag PRE_STANDARD_LMT; (4) IANA `ZoneId.of(zoneId).rules.getOffset(t)`, flag DST iff `rules.isDaylightSavings(t)`. Add HISTORICAL_VERIFY when zone ∈ overlay `verifyZones` and t < `verifyUntilUtc`, or source = OVERLAY.
**4.5 localToInstant:** L = local as if UTC (epoch s). oa = f(L − 86 400), ob = f(L + 86 400). Solutions S = {o ∈ {oa, ob} : f(L − o) == o}. |S| = 1 → unique. |S| = 2 → AMBIGUOUS; EARLIER = L − max(S), LATER = L − min(S), `alternative` = the other. |S| = 0 → gap: instant = L − oa, flag GAP_SHIFTED (= wall time moved forward by the gap; matches `java.time` and Python fold=0). Assumes ≤ 1 transition within ±1 day (true for all tzdata zones and the overlay).
**4.6 civilDayOffset:** resolve local noon of `date` by 4.5. Unique → Valid. AMBIGUOUS → Valid(offset before = max(S)). Gap at noon: if local 00:00:00 and 23:59:59 of `date` are also gaps → Nonexistent (Apia 2011-12-30, Kiritimati 1994-12-31; callers skip the date and never call the engine); else Valid(f(L_noon − oa)) i.e. offset after the gap, flag GAP_SHIFTED. This is M03's "offset in force at local noon".
**4.7 Overlay `rules/tz_overlay.json`** (status VERIFY; schema 1): `entries[] {id, key, offsetSeconds|null, fromUtc, untilUtc, status, source}`, `verifyZones`, `verifyUntilUtc`. Rows: `bombay_time` key bombay 17 460 s (+4:51) [1899-12-31T19:09:00Z, 1954-12-31T19:09:00Z) VERIFY; `calcutta_time` key calcutta 21 200 s (+5:53:20) [1899-12-31T18:06:40Z, 1947-12-31T18:06:40Z) VERIFY ("until 1955/1948" read as local 1 Jan; exact switch dates TODO(owner)); `madras_time`, `karachi_pre1947`, `lahore_pre1947`, `dhaka_pre1947`: offsetSeconds null, status TODO_OWNER, range [1899-12-31T00:00:00Z, 1947-08-15T00:00:00Z). War time (+6:30, 1942–45) comes from IANA `Asia/Kolkata`; no overlay row (whether it overrode Bombay/Calcutta local time is VERIFY). `verifyZones` = Asia/Kolkata, Asia/Karachi, Asia/Dhaka; `verifyUntilUtc` 1956-01-01T00:00:00Z. Parser rejects: duplicate id, from ≥ until, overlapping ranges for one key, |offset| outside engine range.
**4.8 Seed TSV** (UTF-8, header row, tab-separated): `id name admin1 cc lat lon elevM pop zone overlay alt status`; ids 2 000 000 001..; alt `|`-separated; lat/lon ≤ 4 decimals; elevM/admin1/overlay/alt may be empty; status VERIFY on every row. ≤ 200 rows, hand-written from general knowledge (never from GeoNames or any other dataset). Must include: the 10 M01 cities with lat/lon copied from `tools/oracle/gen_riseset.py`; Prayagraj (alt Allahabad|प्रयागराज|इलाहाबाद); Mumbai overlay bombay (alt Bombay|मुंबई); Kolkata overlay calcutta (alt Calcutta|कोलकाता); Chennai (alt Madras), Bengaluru (Bangalore), Varanasi (Benares|Banaras), Pune (Poona), Vadodara (Baroda), Ujjain, Ahmedabad, Surat, Rajkot, Nagpur, Nashik, Karachi, Lahore, Dhaka, Kathmandu, Colombo, Apia, Kiritimati, Santiago, Sydney, plus diaspora hubs (UK, US, CA, AE, SG, MY, AU, NZ, FJ, KE, ZA, MU, TT, GY, SR). Population rounded to 2 significant figures. Parser rejects bad column count, duplicate id, out-of-range lat/lon, zone not in `ZoneId.getAvailableZoneIds()`, overlay key not in overlay file.
**4.9 DB (B7)** inputs, never fetched by code: `cities5000.txt`, `admin1CodesASCII.txt`, optional `alternateNamesV2.txt`, via `--input-dir`. cities5000 columns: 0 id, 1 name, 4 lat, 5 lon, 8 cc, 10 admin1, 14 population, 15 elevation, 16 dem, 17 timezone (elev = col 15, else col 16 unless −9999). Alt names: isolanguage in `--langs` (default `en,hi,mr,gu`, VERIFY extend to all 12 locales) or isHistoric = 1 for cc IN/PK/BD; drop isColloquial = 1 and codes link, post, iata, icao, faac, abbr, wkdt. Then add `diaspora.tsv` (seed format), `renames.tsv` (cc, name, alt) and `overlay_tags.tsv` (cc, name, overlayKey; only Mumbai→bombay, Kolkata→calcutta). Schema `schema.sql`: `place(id INTEGER PRIMARY KEY, name, admin1, cc, lat_e5 INTEGER, lon_e5 INTEGER, elev_m INTEGER, population INTEGER, zone, overlay)`, index on lat_e5; `CREATE VIRTUAL TABLE place_name USING fts4(key, display, place_id, notindexed=display, notindexed=place_id, prefix="2,3", tokenize=simple)`; `meta(k PRIMARY KEY, v)` with schema_version, input sha256s, attribution id. FTS4 not FTS5 (see Decisions). Insert sorted by id, `VACUUM`, page_size 4096. Size gate 6 000 000 bytes: if over, drop alt names of places with population < 15 000, then < 50 000; never drop place rows; still over → exit 1. Rows whose zone is not a valid IANA id → exit 1. FTS MATCH (B8): tokens of NameKey joined by space, each suffixed `*`; tokens contain only L/M/Nd chars so no escaping; fetch ≤ 500 candidates, rank with 4.2.

## 8 Decisions (log in docs/DECISIONS.md)
- D1 FTS4 instead of MASTER's FTS5: platform SQLite (minSdk 24) is not guaranteed to ship FTS5 and no SQLite library is cached; revisit when SQLCipher (bundles FTS5) lands in M06. VERIFY.
- D2 Resolver lives in `:core:geo` on `java.time` (desugared; on API 24–25 tz rules come from desugar_jdk_libs' bundled tzdb, on 26+ from the OS); `:engine` keeps taking an offset; kotlinx-datetime does not expose transitions.
- D3 Overlay boundaries are UTC instants of local 1 Jan of MASTER's "until" year; overlay rows win over IANA war time for keyed places; both VERIFY.
- D4 LMT = round(lon × 240 s) before 1900 or before the zone's first transition (IANA LMT is the reference city's, wrong for other places).
- D5 Gap → shift forward (instant L − offset before); overlap → EARLIER by default with `alternative` exposed for the UI; civil day uses the noon offset, Nonexistent dates are skipped.
- D6 Seed ids 2 000 000 001+ (GeoNames ids stay below); profiles (M06/M10) must store the full place snapshot, not just the id, so a DB update never moves a saved chart.
- D7 No new permission: the one-shot `ACCESS_COARSE_LOCATION` is already in Part 5 and is implemented with its rationale in M07; M05 only supplies `nearest()`.
- D8 Unit tests use the host JDK tzdb; the on-device offset test MASTER §9 asks for is TODO(owner) (no androidTest libs cached).
