# M02 Jyotish core: spec
## 1. Goal and scope
Pure-Kotlin jyotish layer in `:engine` (package `jyotish`) on top of M01: ayanamsa, sidereal positions, houses, nakshatra/pada, Avakhada, vargas D1–D60, Vimshottari (5 levels) and Yogini dashas, yoga/dosha detectors from a JSON DSL, gochar, `ChartFacts`.
Correctness is pinned by the 4 IAE ayanamsa values plus independent Python oracles (offline; no new download, no new dependency). The engine returns codes and ids only, never prose.
Implements MASTER Part 12 "M02"; Part 3 §1 (rows Lahiri, Dasha), §4, §5, §8; Part 2 D2, D3, D5, D9; OVERVIEW C1, C10, C11, C13, C14. M01 is not re-specified.

## 3. Algorithms and rules
**3.1 Zodiac [C1].** s = min(11, floor(lon/30)) (0 = MESHA); d = lon − 30·s. q = min(107, floor(lon·108/360)); nakshatra n = q div 4 (0 = Ashwini), pada = q mod 4 + 1. `nakshatraLord(n)` = [KETU, VENUS, SUN, MOON, MARS, RAHU, JUPITER, SATURN, MERCURY][n mod 9]. `houseFrom` = ((target − ref) mod 12) + 1.
- Sign lords, MESHA..MEENA: MARS, VENUS, MERCURY, MOON, SUN, MERCURY, VENUS, MARS, JUPITER, SATURN, SATURN, JUPITER. Exaltation sign: SUN MESHA, MOON VRISHABHA, MARS MAKARA, MERCURY KANYA, JUPITER KARKA, VENUS MEENA, SATURN TULA; debilitation = the 7th sign from it; RAHU, KETU -> null (VERIFY).
- Aspects (sign offsets counted as houses from the graha): all of SUN..SATURN 7; MARS also 4, 8; JUPITER also 5, 9; SATURN also 3, 10; RAHU, KETU -> empty set (VERIFY). Classes of s: odd sign = s mod 2 == 0; modality = s mod 3 (0 movable, 1 fixed, 2 dual); element = s mod 4 (0 fire, 1 earth, 2 air, 3 water).

**3.2 Ayanamsa [C2].** T(tt) = (tt − 2451545.0)/36525; Δψ = `EarthOrientation.nutation(tt).dpsiRad` (IAU 2000B). pA(T) = 5029.0966·T + 1.11113·T² − 0.000006·T³ arcsec (IAU 1976 general precession in longitude; Lieske et al. 1977, A&A 58, 1).
- LAHIRI (Calendar Reform Committee 1955; value as published in the Indian Astronomical Ephemeris, MASTER §4): true ayanamsa = 23°15′00.658″ = 83700.658″ at t0 = TT JD 2435553.5 (1956-03-21 0h). A_mean(tt) = 83700.658″ − Δψ(t0) + pA(T(tt)) − pA(T(t0)); A_true = A_mean + Δψ(tt). Δψ(t0) is computed once from our nutation, not typed in.
- TRUE_CHITRA (Spica at sidereal 180° exactly; VERIFY the definition and the constants). Spica, HIP 65474, ICRS at epoch J2000.0: α0 = 201.2982474°, δ0 = −11.1613195°, μα·cos δ = −42.35 mas/yr, μδ = −30.67 mas/yr (Hipparcos new reduction, van Leeuwen 2007; typed without catalogue access: TODO(owner) confirm). y = (tt − 2451545.0)/365.25; p0 = (cos δ0 cos α0, cos δ0 sin α0, sin δ0); eα = (−sin α0, cos α0, 0); eδ = (−sin δ0 cos α0, −sin δ0 sin α0, cos δ0); p = unit(p0 + y·(μα·eα + μδ·eδ)), μ in rad/yr. v = `EarthOrientation.gcrsToEclipticOfDate(tt, dpsiRad = 0.0)`·p (mean ecliptic and equinox of date); λ = atan2(v_y, v_x); A_mean = wrap360(λ − 180°); A_true = A_mean + Δψ(tt). No parallax, radial velocity, aberration or deflection.
- KP_NEW, RAMAN, YUKTESHWAR: no constants in M02 (C10). `isEnabled` = false; `meanDeg`/`trueDeg` throw `AyanamsaUnavailableException`. Do not guess epoch values. `isEnabled` is true for LAHIRI and TRUE_CHITRA only.
- `siderealDeg` = wrap360(tropicalLon − A_true). Sidereal speed = tropical speed − (A_true(tt + h) − A_true(tt − h))/(2h), h = 0.005 d.

**3.3 Houses [C3].** `angles`: ut1 = `TimeScales.ut1`, tt = `TimeScales.utcToTt`; θ = LAST = wrap360(deg(`gastRad(ut1, tt)`) + lonDeg); ε = `meanObliquityRad(tt)` + `nutation(tt).depsRad`.
- `tropical` (true equinox of date): asc = atan2(cos θ·cos φ, −(sin θ·cos ε·cos φ + sin φ·sin ε)); mc = atan2(sin θ, cos θ·cos ε); both wrap360. This is MASTER's formula multiplied through by cos φ ≥ 0 (finite at the poles). The ascendant is by definition the RISING (eastern) intersection, as in the 3.10 oracle: if the candidate's hour angle H = θ − α(asc) has sin H > 0 (west of the meridian; only possible for |φ| > 90° − ε) add 180° (amended by the orchestrator 2026-11-14, see DECISIONS; VERIFY with pandit).
- WHOLE_SIGN: starts_i = 30·((floor(asc/30) + i − 1) mod 12), cusps = starts. EQUAL: cusps_i = asc + 30(i − 1), starts_i = cusps_i − 15° (lagna is the bhava madhya; VERIFY).
- SRIPATI (Porphyry; cusps are bhava madhya): A = wrap360(asc − mc); c10 = mc, c11 = mc + A/3, c12 = mc + 2A/3, c1 = asc, c2 = asc + (180 − A)/3, c3 = asc + 2(180 − A)/3, c_{i+6} = c_i + 180°. starts_i (sandhi) = c_{i−1} + wrap360(c_i − c_{i−1})/2.
- PLACIDUS: if |φ| > 66.0° -> `Unavailable(PLACIDUS_HIGH_LATITUDE)`. Else c1 = asc, c10 = mc, and for cusp k with (α_start, rule): 11 (θ + 30°, α = θ + D/3); 12 (θ + 60°, α = θ + 2D/3); 2 (θ + 120°, α = θ + 180° − 2N/3); 3 (θ + 150°, α = θ + 180° − N/3). Iterate: λ = atan2(sin α, cos α·cos ε); δ = asin(sin ε·sin λ); D = acos(−tan φ·tan δ), N = 180° − D; new α by the rule; stop when |wrap180(Δα)| < 1e-11°, max 100 passes, else `Unavailable(NO_CONVERGENCE)`. Cusp = the final λ, wrap360. c5 = c11 + 180°, c6 = c12 + 180°, c8 = c2 + 180°, c9 = c3 + 180°. starts = cusps. (Semi-arc definition: the cusp-11/12 point has travelled 2/3, 1/3 of its diurnal semi-arc from rising; cusps 2/3 likewise below the horizon. The fixed point contracts by ≤ 2/3·tan φ·tan ε < 0.65.)
- `houseOf(lon)` = the i with wrap360(lon − starts_i) < wrap360(starts_{i+1} − starts_i). `sidereal`: A = A_true(settings.ayanamsa, tt); asc, mc, cusps, starts each minus A (wrap360); WHOLE_SIGN is rebuilt from the sidereal asc.

**3.4 Dashas [C4].** Input: Moon sidereal longitude, birth Instant, Y = `year.days`. x = lon·27/360; n = min(26, floor(x)); f = x − n (elapsed fraction).
- VIMSHOTTARI order and years: KETU 7, VENUS 20, SUN 6, MOON 10, MARS 7, RAHU 18, JUPITER 16, SATURN 19, MERCURY 17 (total 120); first lord index i0 = n mod 9; `maxDepth` 5; `maha` = 9 periods (one cycle).
- YOGINI (VERIFY; UI flag off, C14): order = enum order, years 1..8 (total 36); i0 = (n + 3) mod 8 (n 0-based: Ashwini -> BHRAMARI, Ardra -> MANGALA); `maxDepth` 3; `maha` = 32 periods (4 cycles).
- Maha j (j = 0..): lord = order[(i0 + j) mod m]; startDay_0 = −f·years[i0]·Y; duration = years·Y; startDay_{j+1} = endDay_j. Children of a period (s, e, last lord P): d = e − s; child k (0..m−1) has lord order[(idx(P) + k) mod m], startDay = s + d·c_k/total, endDay = s + d·c_{k+1}/total with c_k = sum of the years of the first k children; the last child's endDay = e exactly. `children` on a period at `maxDepth` throws.
- Instants: start = birth + roundToLong(startDay·86,400,000) ms (same for end); day arithmetic is on the UTC Instant line (no leap seconds). `at(t, depth)`: xd = (t − birth) in ms / 86,400,000.0; at each level pick the period with startDay ≤ xd < endDay; t outside `maha` -> `IllegalArgumentException`.

**3.5 Chart assembly [C5].** tt = `utcToTt(at)`. Body per graha: SUN..SATURN by name; RAHU = RAHU_TRUE or RAHU_MEAN and KETU = KETU_TRUE or KETU_MEAN per `settings.node`. lon = `Ayanamsa.siderealDeg(geoApparent.lonDeg, …)`, lat unchanged, speed per 3.2, `retrograde` = speed < 0. Houses = `Houses.sidereal`; if `Unavailable` use WHOLE_SIGN and set `houseFallback = true`. `GrahaFact.house` = WHOLE_SIGN: `houseFrom(lagna, rashi)`; else `houseOf(lon)`. `backend` = `(eph as? SelectingEphemeris)?.backendFor(tt)`. All derived fields are filled in `ChartFacts.fromLongitudes` (also used by tests to build synthetic charts).

**3.8 Yoga DSL [B3].** `R/yogas.json` = `{"version":1,"rules":[{"id","category":"YOGA"|"DOSHA","status":"VERIFY","variant","sourceId","contentId","when":COND}]}`. Term T = `"SUN"`..`"KETU"` or `{"lord_of":h}` (lord of the rashi of house h from lagna). REF = `"LAGNA"` or T. Houses are always counted by sign (`houseFrom`), whatever `houseSystem` is. COND = an object with exactly one key:
- `all:[COND]`, `any:[COND]`, `not:COND` · `in_house:{graha:T, from:REF, houses:[1..12]}` · `in_kendra:{graha, from}` (houses 1, 4, 7, 10) · `in_trikona:{graha, from}` (1, 5, 9) · `none_in_houses:{grahas:[T], from:REF, houses:[..]}`
- `conjunct:[T1,T2]` (same rashi) · `aspect:{by:T1, on:T2}` (`houseFrom(rashi(T1), rashi(T2))` ∈ `aspectsOf(T1)`) · `exchange:[T1,T2]` (each in a rashi owned by the other) · `exalted:T`, `debilitated:T`, `own_sign:T` (false for nodes) · `all_in_arc:{grahas:[T], from:T, to:T}` (every g has 0 < wrap360(lon_g − lon_from) < wrap360(lon_to − lon_from), strict). ## 7. Decisions (log in `docs/DECISIONS.md`)
- §1 "dasha exact to the minute" is gated as ≤ 1 ms arithmetic on the same Moon longitude (C11). Two Moon longitudes 0.05″ apart move a 20-year boundary by about 11 minutes, so end-to-end agreement is bounded by the sidereal gate, not by the minute.
- TRUE_CHITRA uses Spica's catalogue place plus proper motion on the mean ecliptic of date (no aberration: a smooth ayanamsa, nutation cancels as for Lahiri). KP_NEW/RAMAN/YUKTESHWAR stay disabled with no constants (C10).
- The IAE numbers are used as published facts quoted in MASTER §4; nothing else is taken from Swiss Ephemeris material. Lahiri keeps IAU 1976 pA while positions use IAU 2006 (the definition, MASTER §4).
- Houses are gated in two parts (pure geometry at 1e-7°, LAST and obliquity at 0.02″ / 0.005″) because the ascendant amplifies sidereal-time differences at high latitude. Placidus is unavailable above |φ| = 66.0° and the chart falls back to WHOLE_SIGN with a flag. EQUAL takes the lagna as bhava madhya.
- Yoga predicates count houses by sign for every house system. All shipped yoga rules are `VERIFY`. `ChartFacts` lives in `:engine` (not `:core:model`) with a redacted `toString`. kotlinx-serialization-json (tree API) moves to `commonMain` (allowed by Part 4). `rules/` sits at the repo root and is passed to the engine as strings.
