# M09 Calendar UI, regional views, ICS, "Should I…?"
**Goal:** an offline month calendar computed by the engine for the user's place and zone, with a day sheet, festival guide, grahan list, transits list, Marathi/Gujarati views, `.ics` share and rule-based "Should I…?".
**Implements:** MASTER M09 entry (l.1490); Part 2 §B B1–B6 (B6 R1 regions = mr, gu: l.1676, OVERVIEW C12); M1; M7 (share-sheet part); M9 proof panel; Part 11 M09 row (all BUILD, implementer; architect = this spec + Should-I rules).

## Scope / out of scope
- In: month grid (B1); festivals/vrats filtered by tradition (B2, M04 `FestivalEngine` as-is); place + zone everywhere, never IST (B3); grahan list (B4); transits/retrogrades + Adhik maas notice (B5); MARATHI and GUJARATI views (B6); day sheet; festival guide pages; one-off `.ics` share (M7); "Should I…?" (M1).
- Out: device-calendar write / `WRITE_CALENDAR` (D3); family dates in ICS (M10); B7–B10; Tamil/Malayalam/Bengali/Odia views (M04 engine only, flagged off until pandit review); voice mic (D5); ads (M15); lore/katha text (M11 packs); regional festival sets (only region "all" ships, M08 D10); Roborazzi (not cached, M08 decision).

## Data flow
1. `CalInputs(place: Place, placeId: RecordId, zone: TimeZone, offsetFor: (LocalDate) -> Int, calc: CalcSettings, monthSystem: MonthSystem, ekadashi: Tradition, view: CalendarView)` from `AppSettings` + `PlaceRepository`; the M08 session travel place wins if set. No place → `MonthUi.NoPlace`.
2. `MonthModel.show(ym)`: cache hit → emit. Else emit `Loading(stale = last Content)` (grid stays visible, dimmed), compute on the `compute` dispatcher via `CalendarEngine` (in the app: under `EngineAccess`'s single lock, M08 D14), emit `Content`, then prefetch ym±1 (skipped if cached).
3. `MonthCache`: in-memory LRU of 6, key `MonthKey`. Never on disk. `MonthModel` lives in an activity-scoped ViewModel, so rotation/config changes never recompute.

## Rules
- **Grid:** `firstDow = WeekFields.of(locale).firstDayOfWeek`; `gridFirst` = last `firstDow` ≤ day 1; rows = ceil((offset + monthLength)/7) (4–6); n = rows×7. Weekday header = `DayOfWeek.getDisplayName(TextStyle.SHORT, locale)`. Layout is mirrored in RTL by Compose; do not hard-code left/right.
- **Engine calls per month (`DirectCalendarEngine.month`):** `CalendarCalculator.days(gridFirst−1, n+2, …, offsetFor)`, `PanchangCalculator.days(gridFirst, n, …)`, `FestivalEngine.occurrences(defs, gridFirst, gridFirst+n-1, …)`, eclipses from the year list filtered to the grid. `CivilDayOffset.Nonexistent` → `MonthUi.Error(nonexistent = true)`; a `PanchangUnavailableException` day keeps its cell with tithi from `CalendarDay` and no nakshatra (−1).
- **TithiMark** (engine numbers only, t = `tithiAtSunrise`, `cal` requested from gridFirst−1 with count n+2 so every cell has both neighbours): VRIDDHI if t[i] == t[i−1]. KSHAYA_NEXT if (t[i+1] − t[i] + 30) mod 30 == 2 (tithi t[i]+1 begins and ends within day i).
- **Nakshatra** = `pan[i].atSunrise(LimbKind.NAKSHATRA).index`.
- **Tradition filter:** drop occurrences of defs with `rule is FestivalRule.Ekadashi && rule.tradition != ekadashi`.
- **Markers** (by occurrence id, rules/festivals/recurring.json): EKADASHI ← `ekadashi_smarta|ekadashi_vaishnava` (after filter); PURNIMA ← `purnima`; AMAVASYA ← `amavasya`; SANKRANTI ← `sankranti`; ECLIPSE ← `LocalEclipse.visible != null` and the local date of `visible.start` (via `offsetFor`) is the cell date. Marker ids are excluded from the festival dots.
- **Festival dots:** `festivalIds` order = defs with non-empty `vratRules` first, then `pan_india` before `recurring`, then id. Cell shows ≤ 2 dots + "+N"; the day sheet lists all.
- **Header:** distinct `amanta` or `purnimanta` labels (per `monthSystem`) in grid-month order; `masaChanges` = dates whose label differs from the previous day; `adhika` = first label with `adhika == true`; samvat of day 1.
- **B6 views** (both amanta regardless of `monthSystem`, VERIFY pandit TODO(owner)): MARATHI → `samvat.shaka`, paksha labels `cal_paksha_short_mr_*` = "शु." / "कृ."; GUJARATI → `samvat.vikramKartikadi` (changes on Kartika Shukla 1), labels "સુદ" / "વદ" (`translatable="false"`, from MASTER B9). tithiInPaksha = ((t−1) mod 15)+1, paksha = SHUKLA if t ≤ 15. Numerals via `NumberFormat.getInstance(Locale("mr"|"gu"))` only when the UI locale matches. Gate: `RegionalViewsGate.enabled = BuildConfig.DEBUG || ownerSignedOff` (const false until TODO(owner)); hidden otherwise.
- **Day sheet** (ModalBottomSheet, `selected`): Gregorian full date; M08 `LimbCards` + `rangeRefs`/`dayRef` ("next day" marks); sunrise/sunset; masa (amanta + purnimanta), samvat, ritu, ayana; festivals with `kalaWindow`, `muhurat`, `parana` + `OccFlag` badges (vriddhi/kshaya/adhika); eclipse contacts, visibility, sutak; "Should I…?" entry; "How calculated" → `ExplainSheet` with M08 `ProofCopy`; footer "Traditional interpretation, not a scientific prediction."
- **Festival guide** (`Dest.FestivalGuide(id)`): name `fest_name_<id>`; next 3 dates from `festivalsYear(y)` and `(y+1)` with kala window; rule summary rendered from def fields as labels (tithi, paksha, masa, system, kala); `status` + `sourceId`; body = "More details coming" (no lore). Names: English, own words, one per shipped id (37: 27 in pan_india + 10 in recurring), all VERIFY spelling.
- **Grahan (B4)** (`Dest.Grahan`): year selector; per eclipse kind, greatest (local time), magnitude, contacts P1…P4/C1…C4 in local time, `visible`, `sutak`; `local == null || visible == null` → greyed "Not visible here".
- **Transits (B5)** (`Dest.Transits`, month): `Gochar.ingresses(g, from, to)` for every `Graha` except MOON; SignChange with "(retrograde)" when flagged. Stations for MERCURY, VENUS, MARS, JUPITER, SATURN: `ChartCalculator.compute(local noon of each date, place).of(g).retrograde`; a flip between consecutive dates → `Station(date)` shown as "around <date>" (D4). Adhik maas notice from `MonthHeader.adhika`.
- **Jump / pick:** month/year picker years = today.year−50..+50 (D7); "Today" button → `today()`; "Jump to festival" = searchable list of `festivalsYear(currentYear)` names → `jumpTo`.
- **ICS (RFC 5545):** lines end CRLF; content lines folded so no line exceeds 75 octets (continuation = CRLF + one space; never split a UTF-8 sequence). `BEGIN:VCALENDAR`, `VERSION:2.0`, `PRODID:-//ShubhVela//Calendar 1//EN`, `CALSCALE:GREGORIAN`, `METHOD:PUBLISH`; each `VEVENT`: `UID:<UUID>@shubhvela.invalid`, `DTSTAMP:<UTC yyyyMMdd'T'HHmmss'Z'>`, `DTSTART;VALUE=DATE:yyyyMMdd`, `DTEND;VALUE=DATE:<date+1>`, `SUMMARY:<escaped>`, `TRANSP:TRANSPARENT`. TEXT escape `\`→`\\`, `;`→`\;`, `,`→`\,`, newline→`\n`. Content: public festivals/vrats of the chosen year after the tradition filter, all-day only (no times, place, coordinates, names). File `cacheDir/share/<UUID>.ics` (M08 share dir + its start-up cleanup), `FileProvider`, `ACTION_SEND` `text/calendar`, `FLAG_GRANT_READ_URI_PERMISSION`.
- **Should I…? (M1):** `rules/should_i.json` = `{"version":1,"intents":[{id, avoid, prefer, tithiAvoid, vaarPrefer, nakshatraPrefer, status:"VERIFY", sourceId}]}`. v1 ships 30 ids: vehicle_purchase, vehicle_delivery, property_purchase, property_registration, griha_pravesh, construction_start, new_job_join, job_interview, business_start, shop_opening, contract_signing, investment, gold_purchase, electronics_purchase, clothes_purchase, travel_start, pilgrimage_start, haircut, mundan, naming_ceremony, vidyarambha, exam_start, new_course, engagement_talk, gift_giving, puja_start, vrat_start, planting, moving_house, bank_account_open. Every entry: `avoid` = M08 header I-set, `prefer` = {AMRIT, SHUBH, LABH}, the three lists empty, `sourceId: "pp-v1-header-rule"` (no traditional per-intent rule invented; TODO(owner) fixture).
- **ShouldI.answer** (G = prefer-choghadiya ∪ ABHIJIT windows minus avoid windows, over D's daytime then D+1): days empty or D has no sunrise → UNAVAILABLE. tithi ∈ tithiAvoid, or vaarPrefer ≠ ∅ and D.vaar ∉ vaarPrefer, or nakshatraPrefer ≠ ∅ and sunrise nakshatra ∉ it → NOT_FAVOURED_TODAY (whyIds name each failed check; best = null). now ∈ G → GOOD_NOW(best = that interval). G interval later in D's daytime → GOOD_LATER. Else first G in D+1 → TOMORROW, none → UNAVAILABLE. Output order: verdict line → best window → expandable "why" (whyIds → strings) → footer. Copy: "Good time now, until 2:40 PM" / "Better later today: 4:10–5:40 PM" / "Tomorrow from 6:31 AM"; never "bad", "danger", "avoid at all costs", no remedies. Input: a text filter over the 30 labels (`should_i_<id>`), no free-text NLP.
