# M03 Panchang: spec
## 1. Goal and scope
Pure-Kotlin panchang layer in `:engine` (package `panchang`) on M01/M02: five limbs (+ Moon rashi) with exact start/end instants, kshaya/adhika flags, day windows, choghadiya, hora, tarabala/chandrabala, `PanchangDay` API. Engine returns ids, codes and Instants only.
Implements MASTER Part 12 "M03"; Part 3 §1 (limb row), §3 (sunrise, high latitude), §6, §8 (limb oracle, boundary cases, performance); Part 2 A1-A5 (engine side); OVERVIEW C6, C13, C14, C15. M01/M02 are not re-specified.
**Out of scope:** masa, samvat, ritu, ayana, festivals, eclipses (M04); tz data (M05); UI, explain text, cache per (date, place, settings) (M08); moonrise in `PanchangDay` (A2 uses M01 `RiseSet`); lagna table (M08 from M02 `Houses`); Do-ghati, Vijaya, Godhuli, night Rahu/Gulika, Panchak subtypes, Bhadra loka, chandrabala "good houses", tara good/bad: no definition in MASTER (C13) -> TODO(owner), not built.
Tags: **[C1..C3]** CRITICAL (engine-dev: contract, limb solver, windows), **[B1..B4]** BUILD (implementer: tables, parser, oracle, golden, benchmark). Files are disjoint. Order: C1 -> {C2 then C3} in parallel with {B1, B2}; C3 needs B1 merged; then B3 (needs C3, B2), then B4. `*` = MASTER silent; set here; VERIFY; may only be tightened.

## 3. Algorithms and rules
**3.1 Limb functions [C2].** tt = `TimeScales.utcToTt(t)`; λ☉, λ☾ = `eph.positionOnly(SUN|MOON, tt).lonDeg` (geocentric apparent, true ecliptic of date); A = `Ayanamsa.trueDeg(s.ayanamsa, tt)`. F: TITHI, KARANA: E = wrap360(λ☾ − λ☉) (tropical, no ayanamsa); NAKSHATRA, MOON_RASHI: M = wrap360(λ☾ − A); YOGA: Y = wrap360(λ☾ + λ☉ − 2A). Index j0 (0-based) = min(n − 1, floor(F·n/360)); reported index = j0 + 1 for TITHI, KARANA, else j0. One sample evaluates all five F (shared λ☉, λ☾, A).
- Boundary of span j0: B_lo = j0·360.0/n, B_hi = ((j0 + 1) mod n)·360.0/n; g_B(t) = wrap180(F(t) − B) (deg). All F increase monotonically (dE/dt ≥ 10°/d, dM/dt ≥ 11.5°/d), so the step change (≤ 1.4°/2 h) never wraps.
- **Grid anchored to the Unix epoch:** t_k = k·7,200 s since 1970-01-01T00:00Z; k0 = floor(at / 7,200 s). End: k = k0+1, k0+2, …, first k with g_Bhi(t_k) ≥ 0, bracket [t_{k−1}, t_k]. Start: k = k0, k0−1, …, first k with g_Blo(t_k) < 0, bracket [t_k, t_{k+1}]. Brackets are always grid cells. `Brent.findRoot` on seconds from the cell's left point, maxBracket = 1.0 s; instant = left point + root rounded to ns. Cap 40 steps (80 h; Moon rashi ≤ 2.6 d) else `IllegalStateException`. Same boundary => same cell and inputs => bit-identical instant from any query.
- `spans(k, from, to)`: first = `spanAt(k, from)`; then chain: next.start = prev.end (no re-solve), index + 1 (TITHI 30->1, KARANA 60->1, others mod n), until a span has end ≥ `to`. Result = spans overlapping [from, to), time order. Solve E at 6° steps once: a TITHI boundary is the KARANA boundary with even karana number (B multiple of 12°), bit-equal. `indexAt` = floor rule on F(at).
- Karana number k (1..60): 1 KIMSTUGHNA; 2..57 [BAVA, BALAVA, KAULAVA, TAITILA, GARA, VANIJA, VISHTI][(k − 2) mod 7]; 58 SHAKUNI; 59 CHATUSHPADA; 60 NAGA (MASTER §6). Vishti numbers: 8, 15, 22, 29, 36, 43, 50, 57.

**3.2 Civil date -> panchang day [C3].** ws = `Instant.fromEpochSeconds(date.toEpochDays()·86,400 − utcOffsetSeconds)` (local midnight of `date` at the caller's offset; caller passes the offset in force at local noon; M05 supplies it). rs = `RiseSet(eph, time)`; Ev = `rs.sunWithFallback(place, ws, s)`, Fv = `rs.sunWithFallback(place, ws + 24 h, s)`.
- sunrise = first RISE of Ev; sunset = first SET of (Ev ∪ Fv, time order) after sunrise; nextSunrise = first RISE of Fv. Unless sunrise < sunset < nextSunrise all exist: `PanchangUnavailableException(NO_SUN_DAY)` (e.g. NEAREST_DAY at a pole). `SUN_FALLBACK` if any of the three `isFallback`; `EXTRA_SUNRISE` if Ev has a RISE after sunset (rise times crossing local midnight, > 60° only). `days()` therefore tiles: nextSunrise(D) = sunrise(D + 1) bit-equal when the offset is unchanged.
- Day = [sunrise, nextSunrise). vaar = `Vaar.of(date)` (weekday of the civil date; changes at sunrise, not midnight). `backend` = `(eph as? SelectingEphemeris)?.backendFor(utcToTt(sunrise))`.
- `limbs[k]` = `spans(k, sunrise, nextSunrise)`. contains(x) ⇔ start ≤ x < end (a boundary exactly at sunrise belongs to the new limb). kshaya ⇔ contains neither sunrise nor nextSunrise; adhika ⇔ contains both (the limb names this day and the next). `atSunrise(k)` = the span containing sunrise (names the day, MASTER §6 udaya rule). End instants after nextSunrise are reported as is. Other kalas (pradosh, nishita, aparahna, arunodaya) are M04, through `limbs.indexAt/spanAt`.

**3.3 Day windows [C3]** (exact integer arithmetic in Long ns: P(a, b, n, i) = a + ((b − a)·i) div n, so part n ends exactly at b). D = (sunrise, sunset), N = (sunset, nextSunrise). Day part p of 8: [P(D, 8, p−1), P(D, 8, p)].
- RAHU_KAAL / YAMAGANDA / GULIKA, day part by weekday Sun..Sat (MASTER §6): Rahu 8 2 7 5 6 4 3; Yamaganda 5 4 3 2 1 7 6; Gulika 7 6 5 4 3 2 1. `part` = the day part. PRINTED_6AM (these three only): a = ws + 6 h, b = ws + 18 h, same parts (90 min each; reproduces MASTER's Rahu clock times for all 7 days; Yamaganda, Gulika VERIFY).
- Muhurta i of 15: day [P(D, 15, i−1), P(D, 15, i)], night likewise on N. ABHIJIT = day 8 (omitted on WEDNESDAY unless `abhijitOnWednesday`, VERIFY). BRAHMA_MUHURTA = night 14 (ends one muhurta before nextSunrise; the one before this day's sunrise is in day D − 1). DURMUHURTA = each slot of `tables.durmuhurta[vaar]`, `part` = muhurta.
- CHOGHADIYA: 8 day parts of D, `code` = `WeekdayTables.dayChoghadiya(vaar)[p−1].name`; 8 night parts of N, `code` = `tables.choghadiya.night[vaar][p−1]`. GOWRI: same 8 + 8 division, codes from `tables.gowri` (absent -> GOWRI in `unavailable`). HORA: 12 parts of D then 12 of N, hora h (1..24) lord = HORA_ORDER[(idx(vaar.lord) + h − 1) mod 7], `code` = lord name.
- From limb spans (not clipped; reported if overlapping [sunrise, nextSunrise)): BHADRA = KARANA spans with VISHTI, `part` = karana number; PANCHAK = a KUMBHA (10) span joined with the following MEENA (11) span, [KUMBHA.start, MEENA.end) (M sidereal in [300°, 360°), MASTER §6), `part` 0; if the day's first MOON_RASHI span is MEENA, its KUMBHA = `spanAt(MOON_RASHI, first.start − 60 s)`; if the last is KUMBHA, its MEENA = `spanAt(MOON_RASHI, last.end + 60 s)` (bit-equal joins by the anchored grid; not added to `limbs`); VARJYAM / AMRIT_KAAL: for each NAKSHATRA span (n, s, e) and each offset g of its table row: [s + (e − s)·g/60, s + (e − s)·(g + 4)/60], `part` = n (absent table -> both in `unavailable`). Windows sorted by (start, kind ordinal, part).
- `shool` = `WeekdayTables.shool(vaar)` (Dishashool = MASTER's soolam/parigaram table, VERIFY). `night` = true for windows from N.

**3.4 Tables [B1]** (classical facts restated; status VERIFY; UI flag off until sign-off, C14). HORA_ORDER = SUN, VENUS, MERCURY, MOON, SATURN, JUPITER, MARS. Day choghadiya (MASTER): cycle C = [UDVEG, CHAR, LABH, AMRIT, KAAL, SHUBH, ROG], c0 = index of the entry whose lord = vaar.lord, part p = C[(c0 + p − 1) mod 7]. Shool Sun..Sat: WEST/JAGGERY, EAST/CURD, NORTH/MILK, NORTH/MILK, SOUTH/OIL, WEST/JAGGERY, EAST/CURD.
- `R/choghadiya.json` = `{"version":1,"status":"VERIFY","sourceId":"src.traditional.unverified","night":{"SUNDAY":[8 ids],…}}` (day rows are not stored: `parse` sets `choghadiya.day` = empty map, the rule above applies). Night rule (VERIFY): n0 = index in C of the lord of the weekday 4 days later; part p = C[(n0 − 2(p − 1)) mod 7]. Anchors: SUNDAY SHUBH AMRIT CHAR ROG KAAL LABH UDVEG SHUBH; TUESDAY KAAL LABH UDVEG SHUBH AMRIT CHAR ROG KAAL.
- `R/durmuhurta.json` = `{"version":1,"status":"VERIFY","sourceId":…,"weekdays":{"SUNDAY":[{"night":false,"muhurta":14}],…}}`. Values (VERIFY): SUN d14; MON d9, d12; TUE d4, n7; WED d8; THU d6, d12; FRI d4, d9; SAT d1, d2.
- Gowri schema = choghadiya with `day` and `night`, string ids `[A-Z_]+`; varjyam = `{"version":1,"status","sourceId","rows":[{"nakshatra":"ASHWINI","varjyam":[g…],"amrit":[g…]} × 27 in order]}`, g in [0, 56]. Neither file is shipped (TODO(owner)). `parse` rejects (RuleFormatException): unknown keys, missing weekday, wrong lengths, muhurta outside 1..15, unknown choghadiya id, rows out of order, blank `sourceId`, input over 262,144 chars.
- `Bala.tara` = ((today − natal) mod 27) mod 9 + 1 (MASTER §6); `Bala.chandra` = `Zodiac.houseFrom(natalMoon, transitMoon)`.

**3.5 Oracle [B2]** (Python, offline, M01 venv and kernel, byte-reproducible; never reads `rules/*.json` or engine output; own typed copies of the 3.3/3.4 tables). λ☉, λ☾ as `gen_positions.py` (`ecliptic_frame`, true of date), times via `oracle_common`; Lahiri true via `jyotish_ref.py`; rise/set by `gen_riseset.py`'s functions, UPPER_LIMB_REFRACTED only; fallback = M01 `sunWithFallback` rule (real iff the window has a RISE and a SET), LOCAL_NOON_PM_6H with culmination = own code (10-min argmax of Skyfield altitude, then golden-section to 1 ms). Boundaries: 3,600 s grid, **bisection** (not Brent) to ≤ 1 ms, midpoint ms; rate = |dF/dt| in ″/s by central difference ± 60 s. Day rule, flags and windows per 3.2-3.3 in Python (float ms, rounded).
- Cities = M01's 10, fixed standard offsets (min): mumbai, delhi, kolkata, chennai, ujjain +330; london 0; newyork −300; auckland +720; suva +720; tromso +60. Dates: block 2026-01-01..2027-12-31 (730) + 100 per city uniform in 1900-01-02..2099-12-30 (`default_rng(20261116 + cityIndex)`) = 8,300 city-days.
- `panchang_limbs.json`: per city `boundaries{KIND:[[indexAfter, ms, rate]]}` covering [sunrise − 3 d, nextSunrise + 3 d] of every day; `days`: [date, srMs, ssMs, nsrMs, noonMs|null, flags (F fallback, X extra sunrise, S sun fragile per M01 3.9, U unavailable), atSunrise ×5, kshaya [[kind, index]], adhika [[kind, index]], fragile [[kind, 0 = sunrise | 1 = nextSunrise]]].
- **Fragile pairs (anti-vacuous):** (day, kind, sunrise instant) is fragile iff a boundary of that kind lies within τ of it; τ = 150 s (> Base worst 120 s + 10 s sunrise), 600 s on F or S days (fallback noon is ill-conditioned).
