## Data flow (Aaj)
1. Inputs: `AppSettings` (M07) → `homePlaceId`, `defaultCalc: CalcSettings`, `monthSystem`, `ekadashi`; `PlaceRepository` → `GeoPlace`; `OffsetResolver.civilDayOffset(date, ctx)`; `Clock`.
2. Active place = `travelPlace ?: homePlace`. No home place → `EmptyState` with a "Choose city" action (onboarding place step).
3. Civil date D = `now` in the place's zone. Compute on `Dispatchers.Default`: `PanchangCalculator.days(D-1, 3, place, s) { civilDayOffset(it) }` (D-1 and D+1 feed the countdown and header across midnight and sunrise), `CalendarCalculator.day(D, …)`, `FestivalEngine.occurrences(defs.forRegion(r), D, D, …)`, `EclipseSearch.global(D 00:00, D+1 00:00)` → `local(…)`, kept only if `visible != null`.
4. Emit `AajUi.Content` as soon as the panchang is ready. Festivals and eclipse fill in later (`festivals = null` means loading). Never block tier 1 on festivals.
5. Cache (app layer, as decided in M03): `AajCache`, an LRU of 8 entries keyed by `AajKey(date, placeId, offsetSeconds, settingsHash)`. In memory only, never on disk.
6. Recompute triggers: local midnight; `days[1].sunrise` and `nextSunrise`; `ACTION_TIMEZONE_CHANGED`, `ACTION_TIME_CHANGED`, `ACTION_DATE_CHANGED` (registered at runtime while Aaj is visible); place, travel or settings change. A 1 s ticker updates only the countdown text, never the compute.
7. Error states: `CivilDayOffset.Nonexistent` → "This date does not exist in this time zone". `PanchangUnavailableException(NO_SUN_DAY)` → "Sun does not rise or set here today", with only limbs shown (via `limbs.spans`).

## Header rule (M5), v1, VERIFY with owner (fixture TODO(owner) `docs/fixtures/aaj-header.md`)
Let A = the day-panchang containing now (`sunrise ≤ now < nextSunrise` over `days`). Let I = windows of kinds {RAHU_KAAL, YAMAGANDA, GULIKA, DURMUHURTA, VARJYAM, BHADRA}. Let G = CHOGHADIYA windows whose `code` ∈ {AMRIT, SHUBH, LABH} (VERIFY set), plus ABHIJIT. "Good" interval = a maximal union of G-intervals minus every I-interval. Evaluate in order:
1. `days` is empty or A has no sunrise → `Unavailable`.
2. now ∈ some I → `WaitUntil(kind with the latest end among the overlapping I windows, that end, nextGood = first Good start ≥ end within A or A+1)`.
3. now ∈ Good → `GoodUntil(end of that Good interval)`; the end is capped at the start of the next I window.
4. A Good interval starts later in A's daytime (before A.sunset) → `NextGood(start, end)`.
5. Otherwise → `TomorrowFrom(first Good start in A+1, or null)`.
Copy (string resources, local time, `DateFormat.is24HourFormat`): "Good for new work until 2:40 PM"; "Rahu kaal until 3:00 PM. Next good time 3:00 PM"; "Next good time 4:10–5:40 PM"; "Today's good times are over. Tomorrow from 6:31 AM"; "Timings unavailable here today". No fear words (Part 2 Tone rules): never "bad", "danger", "avoid at all costs". The footer "Traditional interpretation, not a scientific prediction." appears under the header and in every explain sheet.
Tiers (progressive disclosure): T1 = header + `DayArc` (sunrise→sunset arc, now marker, I in amber, G in green, labelled chips, not colour alone). T2 = `TimeWindowCard` list: the next/active window with a live countdown, then all of today's windows sorted by start, then choghadiya day/night and hora. T3 = "Full panchang" expander: A1 limbs with end times (each `LimbSpan.end`; when it ends after `nextSunrise`, append "(next day)"; kshaya/adhika badges), A2 rise/set, Moon phase and sign, masa (amanta + purnimanta), samvat, ritu, ayana, shool, festivals, eclipse notice, A6 strip.
- `NextWindowRule.SHOWN` = I ∪ {ABHIJIT, BRAHMA_MUHURTA, AMRIT_KAAL}. `next` = the earliest window with `end > now`; `active = start ≤ now`. Searched across all 3 days, so it is correct across midnight and before sunrise.
- Unavailable: every `WindowKind` in `A.unavailable`, plus Vijaya, Godhuli, Do-ghati, the lagna table and Gowri when `tables.gowri == null`: shown as "Not available yet". Never guessed or interpolated.
- High latitude: `DayFlag.SUN_FALLBACK` or `EXTRA_SUNRISE` → an info banner plus a proof-panel line.
- Proof panel (M9) via `ExplainSheet(proof = ProofInfo(backend = day.backend, ayanamsa = s.ayanamsa, sunrise = convention label, altitudeM = place.altitude))` plus the string "Times can differ from other apps by about 1 minute because of sunrise convention, refraction, altitude and ephemeris."
- A6: Tarabalam `Bala.tara(A.atSunrise(NAKSHATRA).index, natal)` and Chandrabalam `Bala.chandra(moonRashi, natalRashi)`, shown as numbers + explain sheet, self profile only. No good/bad label until owner-supplied rules (TODO(owner)).

## Scheduling design (Part 3 §10, L2)
- `ReminderPlanner.plan(now, days14, festivals14, eclipses14, family14, prefs): List<PlannedReminder>`: a pure function over the next 14 days. Rules: VRAT_EVE = 19:00 local on the day before each occurrence whose def has non-empty `vratRules` (including Ekadashi); GRAHAN = 19:00 the evening before a locally visible eclipse; FAMILY_DATES = 19:00 the evening before (source port `FamilyDateSource`, returns empty until M10); SUNRISE_BRAHMA = the start of BRAHMA_MUHURTA. Hours are product choices (Decision D4).
- Cap: at most 2 per local day (L2 default). Keep by priority GRAHAN > VRAT_EVE > FAMILY_DATES > SUNRISE_BRAHMA, then earliest. Drop any trigger ≤ now. Only categories in `AppSettings.reminders` (opt-in per category).
- `AlarmSink.setWindow(id, triggerAt, 2 min)`. Prod: `AlarmManager.setWindow(RTC_WAKEUP, t, 120_000, pi)`. Request code = stable hash of (kind, date). Cancel-all before re-plan. No exact alarms.
- Re-plan on: app start, settings/place change, daily `JobScheduler` job (id 8001, period 24 h, `setPersisted(true)`), `BOOT_COMPLETED`, `TIME_SET`, `TIMEZONE_CHANGED`, `LOCALE_CHANGED`. `ReminderReceiver`, `SystemEventsReceiver`, `ReplanJobService` (`permission=BIND_JOB_SERVICE`) and `FileProvider` are `exported="false"`. System-sent broadcasts still arrive, and code checks the action. Exported components are the widget providers (Part 5's "Glance receivers" slot) and `PanchangTileService` (`permission=BIND_QUICK_SETTINGS_TILE`, required by the platform; Part 5 edit TODO).
- Channels (ids are permanent): `vrat_eve`, `family_dates`, `grahan`, `daily_times`; all `IMPORTANCE_DEFAULT`, `lockscreenVisibility = VISIBILITY_PRIVATE`, each with a `setPublicVersion` ("ShubhVela: a reminder"). Text (resources): "Ekadashi tomorrow. Parana 6:12–8:40 AM"; "Grahan tomorrow, visible 9:02–11:40 PM"; "A family date is tomorrow"; "Brahma muhurta has begun. Sunrise 6:24 AM". No names, no city, no birth data, no dosha, no "bad day" (Part 8). Tap → Aaj.
- `POST_NOTIFICATIONS` (API 33+): if denied, the planner still runs but `Poster` no-ops, and Settings shows "Notifications are off" with a system-settings intent. Never re-prompt automatically.
- Widgets: `updatePeriodMillis=0`. After each render, `setWindow(RTC /*non-wakeup*/, Transitions.nextBoundary, 60_000)`. Rahu countdown via `RemoteViews.setChronometer(countDown=true)`, so there are no per-second updates.

## Widgets (L1), QS tile (M8), travel (M3), read-aloud (M4), share (A8)
- `TodayWidget` 4x2: vaar, tithi + end, nakshatra + end, sunrise/sunset, next window. `NextRahuWidget` 2x1: the next or active Rahu kaal with a chronometer. `FestivalWidget` 2x2: the next festival in ≤ 60 days with "in N days". City shown only if `AppSettings.showCityOnWidgets` (default false). Dark mode via `values-night` colours. Content built by the pure `WidgetContent.today/rahu/festival(now, days, …): WidgetModel`; `RemoteViewsBinder` maps the model to views.
- `PanchangTileService`: label "Rahu kaal 3:00 PM", subtitle = current choghadiya name; updates in `onStartListening` only; tap → Aaj. Before onboarding or with no place → "Set city".
- Travel mode: `AppSettings.travelMode` (default false). On `TIMEZONE_CHANGED` with travelMode on → a banner "Time zone changed. Update timings for where you are?". On tap → in-context rationale → one-shot `ACCESS_COARSE_LOCATION` `getCurrentLocation` → `PlaceSearch.nearest(lat, lon)` → session `travelPlace` (memory only; coordinates are never stored or logged) → "You're in Dubai: timings updated". The home place is unchanged. "Back to home" clears it. No background location.
- Read-aloud: `AajSpeech.script(ui): List<String>` (T1 + T2 strings). `TextToSpeech`: show the speak button only if `isLanguageAvailable(locale) ≥ LANG_AVAILABLE` and the chosen voice has `!isNetworkConnectionRequired` (offline-only voice; Decision D6). Stop on leave.
- Share card: `ShareCardRenderer.render(content, Format.SQUARE_1080 | STORY_1080x1920): Bitmap`, brand colours, city + date + limbs + language; cache dir + `FileProvider` + `ACTION_SEND`; deleted on next app start. No location metadata.
