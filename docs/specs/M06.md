## 4 Crypto design (all big-endian; any deviation = reject, fail closed)
- **Hierarchy.** KEK: Android Keystore AES-256, alias `pp.kek.v1`, `PURPOSE_ENCRYPT|DECRYPT`, GCM, `ENCRYPTION_PADDING_NONE`, `setRandomizedEncryptionRequired(true)`, no user-auth binding, no `setUnlockedDeviceRequired` (D7). API ≥ 28: try `setIsStrongBoxBacked(true)`, on `StrongBoxUnavailableException` regenerate without it. KEK never leaves Keystore. DEK: 32 bytes `SecureRandom`, generation id g ≥ 1 (the future SQLCipher passphrase, D1). K_b (backup key): 32 random bytes, generation g ≥ 1. Cipher for DEK/K_b/export: `javax.crypto` `AES/GCM/NoPadding`, 128-bit tag, 96-bit nonce from `SecureRandom` per encryption (Keystore generates the IV for wraps). Random-nonce bound 2^32 encryptions per key (SP 800-38D); family data is orders of magnitude below; rotation resets.
- **Wrapped key file** `noBackupFilesDir/keys/{dek|kb}.<g>.bin`: `"PPWK"` | u8 ver=1 | u8 purpose (1 DEK, 2 K_b) | u32 g | u8 kekVer=1 | iv[12] | ct+tag[48]. AAD = the 11 header bytes before iv. Write to `<name>.tmp`, fsync, rename.
- **Row envelope** (column `blob`): u8 ver=1 | u32 keyId(=DEK g) | nonce[12] | ct+tag. AAD (27 B) = `"PPR1"` | u8 tbl | id[16] | u16 payloadVer | u32 keyId. tbl: 1 profile, 2 place, 3 bond, 4 settings (id = 16 zero bytes). Plaintext = UTF-8 JSON of the record (B2).
- **Snapshot** `filesDir/backup/snapshot.bin`: `"PPSN"` | u8 ver=1 | u32 K_b g | nonce[12] | ct+tag; AAD = 21 header bytes; plaintext = FamilyDocument JSON. Max 8 MiB.
- **Export** (`.ppx`): `"PPEX"` | u8 ver=1 | u8 kdf=1 (PBKDF2-HMAC-SHA256) | u32 iterations | u8 saltLen=16 | salt[16] | nonce[12] | ct+tag; AAD = 39 header bytes. Write iterations = 600 000 on every API level (D6). Import accepts iterations ∈ [600 000, 5 000 000], saltLen = 16, ver = 1, kdf = 1, total ≤ 8 MiB and ≥ 55 B; read at most 8 MiB + 1 B. Key = PBKDF2(P, salt, c, 32). P = UTF-8 of `Normalizer.normalize(passphrase, NFC)`; policy: ≥ 10 code points else `PASSPHRASE_POLICY`. PBKDF2 = own RFC 8018 §5.2 over `Mac("HmacSHA256")` (`PBKDF2WithHmacSHA256` is absent on API 24-25), run on `Dispatchers.Default`.
- **Errors.** Magic/length/field → FILE_FORMAT; ver/kdf unknown → FILE_VERSION; `AEADBadTagException` → FILE_AUTH (one message: wrong passphrase or damaged file); decode or validation of plaintext fails → FILE_FORMAT. Import decodes everything first, then one transaction; nothing written on any error.
- **Zeroing.** `Bytes.wipe(ByteArray)`/`CharArray` fill(0) in `finally` for passphrase, P bytes, derived keys, DEK/K_b on `close()`/wipe, plaintext JSON byte arrays. `SecretKeySpec` copies and Strings cannot be wiped (accepted, noted in KDoc).
- **Key state (`DataVault.open`).** No wrapped DEK and no rows → if `snapshot.bin` exists and `BackupKeyStore.retrieve()` ≠ null → Restoring (section 5), else create KEK + DEK g=1 → Ready. Wrapped DEK present: unwrap. `KeyPermanentlyInvalidatedException`, `UnrecoverableKeyException`, alias missing, `AEADBadTagException` → KeyLost. `KeyStoreException`/`ProviderException` → retry once after 250 ms, then KeyUnavailable. Never auto-wipe or overwrite a DEK (D8). `startFresh()` = `DataWiper.deleteAll()` then open. Repos return `LOCKED` unless Ready.
- **Rotation.** `DekManager.rotate()`: write `dek.<g+1>.bin`, re-encrypt all rows under g+1 in one transaction, then delete `dek.<g>.bin`; on open load every `dek.*.bin`; rows decrypt by keyId; leftover older file after a crash is deleted once no row uses it. K_b rotation: same pattern (new kb file, rewrite snapshot, `BackupKeyStore.store`, delete old).

## 5 Storage, schema, backup
- DB: `SQLiteOpenHelper` file `pp_family.db` (default databases dir), `PRAGMA secure_delete=ON` on open, `user_version` = `Schema.VERSION = 1`. v1 = `CREATE TABLE record(tbl INTEGER NOT NULL, id BLOB NOT NULL, pos INTEGER NOT NULL DEFAULT 0, ver INTEGER NOT NULL, blob BLOB NOT NULL, PRIMARY KEY(tbl, id)) WITHOUT ROWID;` Clear columns only: tbl, random id, pos (order), payload ver; row count and blob size leak (accepted). No timestamps, names, indexes or FTS in clear.
- Migrations: `Schema.MIGRATIONS: Map<Int, List<String>>` (from → from+1, empty for v1), each step in one transaction; every new version adds `core/data/schemas/v<N>.sql`. `onDowngrade` throws → state KeyUnavailable, repos `IO`, nothing wiped. Payload migrations: `PayloadMigrations` (tbl, fromVer) → `(JsonObject) -> JsonObject`; current payloadVer = 1 for all tables.
- JSON codec (kotlinx-serialization-json tree API, no plugin): fixed key names, every field always written; enums by name, unknown name → reject; Instant ISO-8601 `toString()`/`parse`; doubles as JSON numbers (exact round trip); CalcSettings all 12 fields, missing → that field's default. Limits: displayName 1..60 chars, notes ≤ 2000, profiles ≤ 500, places ≤ 2000, bonds ≤ 2000 (`LIMIT`); at most one Relation.SELF (`SELF_EXISTS`); Bond ranges mn 0..26, mp 1..4, mr/lg/ven/sun 0..11, mars 0..2, name 1..12 chars (else VALIDATION). FamilyDocument = `{"v":1,"profiles":[..],"places":[..],"bonds":[..],"settings":{..}}`.
- Snapshot: `SnapshotManager.writeNow()` (debounced 2 s after changes, and on open if older than 24 h) runs only if `BackupKeyStore.isAvailable()`. M06 binds `UnavailableBackupKeyStore` (false), so no `snapshot.bin` is written in M06 (D4). Restore (Restoring): decrypt with retrieved K_b → new KEK + DEK g=1 → insert all in one transaction → rotate K_b → Ready; any failure → delete the partial DB and new DEK, keep `snapshot.bin` and K_b, state KeyLost (user picks retry, import or start fresh).
- Delete all (`DataWiper`): order KEK alias delete → `noBackupFilesDir/keys/*` → DB close + `deleteDatabase` (db, -journal, -wal, -shm) → `filesDir/backup/*` → `cacheDir/share/*` → `BackupKeyStore.clear()` → wipe in-memory keys; continue past errors, report first error code. `geo_places.db` (not personal) is kept.
- Backup XML, exact (`pp_data_extraction_rules.xml`):
  `<data-extraction-rules><cloud-backup disableIfNoEncryptionCapabilities="true"><include domain="file" path="backup/snapshot.bin"/></cloud-backup><device-transfer><include domain="file" path="backup/snapshot.bin"/></device-transfer></data-extraction-rules>`
  `pp_backup_rules.xml`: `<full-backup-content><include domain="file" path="backup/snapshot.bin" requireFlags="clientSideEncryption"/></full-backup-content>`
  Manifest: `android:allowBackup="true" android:dataExtractionRules="@xml/pp_data_extraction_rules" android:fullBackupContent="@xml/pp_backup_rules"`. Include-only rules exclude the DB and everything else by construction; wrapped keys live in `noBackupFilesDir` (never backed up) (D5). No permission change.
- Strings (`core/data/.../values/strings.xml`, en only, as M05): `data_key_lost_title` "Your saved family data can't be opened on this phone"; `data_key_lost_body` "The phone's security key for this data was reset, so it can't be read. You can restore a backup, import a family file or start fresh."; `data_key_unavailable_body` "Your data is safe but can't be opened right now."; `data_try_again`; `data_restore_backup`; `data_import_file`; `data_start_fresh`; `data_start_fresh_confirm` "Start fresh deletes the unreadable data on this phone. This can't be undone."; `import_error_auth` "Wrong passphrase or damaged file"; `import_error_format`; `import_error_version` "This file is from a newer app version"; `import_error_too_large`; `passphrase_too_short` (%1$d chars); `export_file_name` "family-backup.ppx"; `delete_all_title`; `delete_all_confirm`.

## 8 Decisions (log in docs/DECISIONS.md)
D1 Platform SQLite + per-row AES-256-GCM under a Keystore-wrapped 32-byte DEK instead of Room 3 + SQLCipher; the DEK is the future SQLCipher passphrase, same wrap. D2 JSON (tree API) instead of CBOR. D3 Settings in the encrypted record store instead of DataStore-Tink. D4 Snapshot written only when a BackupKeyStore is available; none in M06. D5 Include-only backup rules (lint rejects excludes outside includes); allowBackup true. D6 Own PBKDF2-HMAC-SHA256, 600 000 iterations on all API levels, NFC passphrase. D7 Data KEK not auth-bound (alerts and widgets need data while locked; app lock is a separate optional key). D8 Key loss never auto-wipes; user chooses. D9 M05 FTS4 stays (no SQLCipher/FTS5). D10 coroutines-core 1.9.0 (already verified). D11 `:core:model` depends on `:engine` for CalcSettings. D12 Instrumented tests replaced by JVM fakes; device runs deferred.
