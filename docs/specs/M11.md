# M11 Content packs and rashifal (spec)
**Goal:** signed, offline, per-language interpretation packs (`:content`) plus a deterministic rules engine that turns real transits into rashifal (H1) and personal daily guidance (H2), shown in `:feature:horoscope`.
**Implements:** MASTER Part 12 M11; Part 9 (two kinds of text, terminology, content pipeline steps 5-6); Part 2 A7, H1, H2, M2, Tone rules; Part 4 `:content`; Part 5 input validation (line 717-718); Part 7 placements; Part 10 §B (signing key is human-only).

## 1. Deviations (log as M11 D1-D3 in docs/DECISIONS.md, each with TODO(owner) to approve)
- **D1 No Tink, pure-Kotlin Ed25519 verify.** Tink is not KMP and not in the catalog (only build-tool transitives in the Gradle cache). Verify in `:content` commonMain (RFC 8032 §5.1.7) with pure-Kotlin SHA-512 (FIPS 180-4). Signing happens only at build time with the JDK's built-in `Signature.getInstance("Ed25519")` (no library).
- **D2 JSON-in-envelope, not CBOR.** `kotlinx-serialization-cbor` is not cached. Payload codec byte 1 = UTF-8 JSON (`kotlinx-serialization-json`, already in catalog); codec 2 = CBOR reserved. Asset path `content/<lang>/pack.ppc` (not `pack.cbor`).
- **D3 Bundled-pack key is ephemeral per build.** `:content:buildPacks` generates a fresh key pair in memory, signs the bundled packs, writes only the public key to `content/bundled.pub`, and discards the private key. This gives integrity only (APK signing gives authenticity). Downloaded packs (M18b) accept only `TrustedKeys.PROD`, which is `emptyList()` with `TODO(owner)`: the owner runs `tools/sign/keygen` and pastes the PUBLIC key. No private key is ever in the repo, the APK, logs or tests on disk. Agents never read `~/.pp-secrets`.

## 3. Rules
**Envelope (big-endian):** `0..3` magic `PPCK`; `4` envelopeVersion=1; `5` codec=1; `6..13` keyId = first 8 bytes of SHA-512(publicKey); `14..17` payloadLen u32; payload; then 64-byte signature over bytes `[0, 18+len)`. Total must equal `18+len+64` exactly.
**Load order (never parse before verify):** size > 24 MiB -> TooLarge (check before anything); length/magic -> Malformed; version or codec != 1 -> UnsupportedVersion; keyId not in keys for source (BUNDLED: `bundled` only; REMOTE: `remote` only) -> UntrustedKey; Ed25519 false -> SignatureInvalid; then JSON decode; then schema: `schema==1`, `lang` == requested lang, every id matches `^[a-z][a-z0-9_]*(\.[a-z0-9_]+)+$`, values non-empty and ≤ 4096 chars, term arrays of exact `TermKind.count` -> else SchemaInvalid.
**Payload JSON:** `{"schema":1,"lang":"hi","version":1,"entries":{id:text},"terms":{"rashi":[12],"graha":[9],"nak":[27],"tara":[9]}}`. Term arrays may be absent in placeholder packs.
**Ed25519 verify (RFC 8032 §5.1.7):** reject if any length is wrong (pk 32, sig 64); decode A and R per §5.1.3 (reject y ≥ p, reject no square root, reject x=0 with sign bit 1); reject S ≥ L; k = SHA-512(R‖A‖M) mod L; accept iff [8][S]B == [8]R + [8][k]A. Field: 16×16-bit limbs in `LongArray` (TweetNaCl layout). Not constant-time (public inputs only; note in KDoc).
**Resolver fallback:** chain `[lang, "en"]` only. Hit in lang -> isFallback=false; hit in en -> isFallback=true; miss -> `IllegalStateException` (lint makes this unreachable for bundled packs). Packs `en, hi, mr, gu` are bundled; `mr, gu` have empty `entries`.
**Template grammar:** `{{`/`}}` literal braces; `{rashi:N}`, `{graha:N}`, `{nak:N}`, `{tara:N}` fixed term refs, N 1-based in range; `{name}` named arg, `name ~ [a-z][a-z0-9_]*`; Term arg -> resolved term, Time arg -> caller formatter (same as Aaj), Text -> verbatim. Unknown arg, missing arg, bad N, unclosed brace -> `Result.failure`; UI then shows en for that line. **No numeric/plural args** (plurals stay in strings.xml ICU). **Gender-safe:** text never inflects a verb for the reader's gender (hi/mr/gu: subject is the day/time/planet, not "आप"); human check (VERIFY V6).
**IDs:** graha codes `su mo ma me ju ve sa ra ke` (= `Graha` ordinals 0..8). `gochar.<g>.h<1..12>.v<k>`; `rf.moon_shift{time,rashi}`; `rf.ingress{graha,rashi,time}`; `rf.retro{graha}`; `rf.tara.t1..t9`; `rf.dasha_lord{graha}`; `rf.chandrashtama`; `rf.sadesati.{rising,peak,setting,dhaiya_4th,dhaiya_8th}`. `REQUIRED` = all those with v1 only (108 + 2 + 1 + 9 + 1 + 1 + 5 = 127).
**House:** `h = Zodiac.houseFrom(sign, rashiOfPlanet)`. **Variant:** `k = floorMod(window.index + sign.ordinal + graha.ordinal, n) + 1`, `n = max(1, variants("gochar.<g>.h<h>"))` from the user-language pack (en if fallback). No randomness, no clock reads inside rules.
**H1 periods** (caller builds windows from the engine's existing panchang-day start, i.e. sunrise per CalcSettings and its no-sunrise fallback):
| Period | window.start / end | index | planets at start |
|---|---|---|---|
| DAY | day start / next day start | civil epochDay | MOON, then `SEC[floorMod(index + sign.ordinal, 8)]`, `SEC=[SUN,MARS,MERCURY,JUPITER,VENUS,SATURN,RAHU,KETU]` |
| WEEK | Monday day start / +7 days (V2) | floorDiv(epochDay of Monday, 7) | SUN, `[MARS,MERCURY,VENUS][index mod 3]`, `[JUPITER,SATURN,RAHU][index mod 3]` |
| MONTH | 1st civil day / 1st of next month | year*12+month-1 | SUN, MARS, VENUS, JUPITER |
| YEAR | 1 Jan / 1 Jan next (V3) | year | JUPITER, SATURN, RAHU, KETU |
Per planet: line `gochar` at start; if retrograde at start and not RAHU/KETU add `rf.retro`. Ingresses in `[start, end)` of listed planets (DAY: Moon only; WEEK+: Moon excluded): earliest first, max 2 per reading; each adds `rf.ingress` (DAY Moon: `rf.moon_shift`) then the `gochar` line for the new house. Order = table order, ingress lines right after their planet.
**H2 personal daily** (sign for variants = natal Moon; houses from natal Moon unless stated): (1) `rf.tara.t{Bala.tara(src.nakshatra(start), natal.moonNakshatra)}`; (2) Moon `gochar` from natal Moon; (3) dasha lord L = MD, or AD if MD is MOON, skip if both MOON: `rf.dasha_lord` then `gochar.<L>` by house **from lagna**; (4) if Moon house from natal Moon == 8: `rf.chandrashtama`; (5) `Gochar.sadeSati(natal.moon, rashi(SATURN))` != NONE: `rf.sadesati.<phase>`. H2 weekly = H1 WEEK with `sign = natal.lagna` plus line (3).
**Lint (`ContentLint`, errors fail):** L1 id regex; L2 every REQUIRED id present in en and hi (direct), resolvable (fallback) in mr, gu; L3 banned terms (en: case-insensitive whole word; Devanagari: substring after NFC) from `banned_<lang>.txt`, seed en: danger, dangerous, destroy, destruction, death, die, deadly, fatal, disaster, curse, doom, ruin, catastrophe, remedy, remedies, gemstone, buy, guaranteed, urgent, "100%"; hi seed VERIFY V5; L4 length: `gochar.*` ≤ 40 words and ≤ 400 chars, `rf.*` ≤ 30 words (words = split on Unicode whitespace); L5 named-arg set per id equals en's; term refs in range; L6 braces balanced; L7 text is NFC, no leading/trailing space; L8 en and hi terms complete; L9 variants contiguous from v1. Output lines `lang id rule` only.
