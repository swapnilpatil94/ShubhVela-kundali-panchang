# M07 Design system, shell, onboarding (all tasks BUILD, implementer)

## 1. Goal and sources
Brand theme and base components, a 5-tab adaptive shell with a vault gate, a 5-step onboarding of 60 s or less that creates settings, a home place and an optional self profile, a search palette, and Settings → Conventions (J4). No ads, no network.
Implements MASTER Part 6 (all), Part 2 IA (5 tabs, palette, settings behind the avatar) plus J4, L2 opt-in, L3 picker and M9 (proof panel in `ExplainSheet`, per OVERVIEW C4), Part 5 PLATFORM permissions, M07 entry (l.1461), and `design/contact-sheet.html` screens 01–03 and 16. M06 D8: no auto-wipe.
**Out of scope:** Aaj/Calendar/Kundli/Bonds/Bhakti content (M08–M13); `TimeWindowCard`, `DayArc`, `PanchangGrid` (M08); `ChartView`, `DashaTimeline` (M10); `BondCard`, `ShareCardFrame` (M12); `RewardedUnlockButton`, ads (M15); translations (M16); delete-all and export/import UI (M10); posting notifications (M08); regional presets (M09).

- Containers: `xContainer = lerp(surface, x, 0.18)` per channel in sRGB, rounded; `onXContainer` = onSurface. The remaining M3 roles keep `lightColorScheme()`/`darkColorScheme()` defaults.
- **Contrast rule (test-enforced):** WCAG 2.x relative luminance and ratio. Every text pair (on* over its role, onSurface and onSurfaceVariant over surface and surfaceContainer, chip fg over chip bg, primary used as text over surface) must be ≥ 4.5; icons and text of 24 sp or more must be ≥ 3.0. If a pair fails, set a `primaryText`/`xText` variant by lowering HSL lightness 1 % at a time (raising it in dark) until it passes. Record the final hex in DECISIONS. Note: #E8772E on #FFF8EE is about 2.8, so light text in primary colour needs `primaryText`. Seed colours are never used as text unless they pass.
- Dynamic colour: opt-in only (`AppSettings.dynamicColor`, API 31+). Off by default. Share cards always use brand colours (M12).
- Type (`DS/tokens/PpType.kt`): the M3 default scale with `bodyLarge` 16 sp, `bodyMedium` 16 sp, `bodySmall` 14 sp (captions only); display and headline styles use `FontFamily.Serif`, everything else `FontFamily.Default` (the system Noto covers all 12 scripts). No fixed heights on text containers; set `lineHeight` only as an em multiple (1.4 em body, 1.75 em Sanskrit, from the contact sheet).
- Bada Text: wrap content in `Density(density, fontScale * 1.2f)`. It stacks with the system scale; the layout must hold at system 2.0 × 1.2.
- Spacing `PpSpace`: 4, 8, 12, 16, 20, 24, 32 dp. Touch targets ≥ 48 dp (`Modifier.minimumInteractiveComponentSize()`).
- Shapes `PpShapes`: small 12 dp, medium 20 dp (cards), large 24 dp, extraLarge 28 dp, sheet top 26 dp, chips and buttons pill (50 %). `LotusPetalShape` is a `GenericShape`: moveTo(w/2,0), quadTo(w,0.55h → w/2,h), quadTo(0,0.55h → w/2,0). Hero brand mark only.
- Motion `PpMotion`: `spring(dampingRatio = Spring.DampingRatioNoBouncy, stiffness = Spring.StiffnessMediumLow)` everywhere (no bounce). `LocalReducedMotion` is true when `Settings.Global.ANIMATOR_DURATION_SCALE == 0f` or `AppSettings.reduceMotion`; motion then uses `snap()`. Pass a `MotionScheme` only if material3 1.4.0 exposes one without opt-in failure; otherwise skip it and log a Decision.
- Elevation: 0 dp. Cards use a 1 dp `outlineVariant` border (contact sheet); sheets use tonal elevation 1.

## 5. Rules
- **Navigation:** each Tab has its own stack, whose root is `Root(tab)`. `select(t)`: if t is the current tab, pop it to the root; otherwise switch tabs and keep both stacks. `back()`: pop if the stack is deeper than 1; else if the tab is not AAJ, switch to AAJ and return true; else return false. Predictive back: `PredictiveBackHandler(enabled = navigator.canGoBack)` calls `back()` on completion. The manifest sets `android:enableOnBackInvokedCallback="true"`. Save and restore via `rememberSaveable` with a Saver over `save()` (stable string keys).
- **Gate (M06 D8):** `DataGraph.start()` runs only in `PanchangApp.onCreate` via `appScope.launch(Dispatchers.IO)`, where `appScope = CoroutineScope(SupervisorJob())`. `PlaceSearch` is injected as `dagger.Lazy` and first called on `Dispatchers.IO`. Vault state maps Opening/Restoring → Loading, Ready → (onboardingDone ? Shell : Onboarding), KeyLost → KeyLost, KeyUnavailable → KeyUnavailable. The KeyLost screen explains that the saved data cannot be read on this device and offers "Start fresh" (a confirm dialog naming what is erased; the button uses `filterTouchesWhenObscured`) and "Close app". KeyUnavailable offers "Try again" (`vault.open()`) plus the same "Start fresh". `retry` and `startFreshConfirmed` are single-flight: while `busy`, both are no-ops and the buttons are disabled. Nothing calls `startFresh()` without a confirmed tap. M07 exposes **no delete-all UI**, so the vault-owned wipe entry point stays open for M10 (log in DECISIONS).
- **Onboarding (5 steps, Part 6):**
  1. **Language.** 12 tiles in native names (`translatable="false"`): en English, hi हिन्दी, bn বাংলা, mr मराठी, te తెలుగు, ta தமிழ், gu ગુજરાતી, kn ಕನ್ನಡ, ml മലയാളം, or ଓଡ଼ିଆ, pa ਪੰਜਾਬੀ, as অসমীয়া. Pre-select the device's primary language if it is in the list, else en. Apply on API 33+ with `LocaleManager.applicationLocales`; below 33, use a plain SharedPreferences `pp_ui`/`locale` (the same pattern as the AppCompat backport; not personal data) read in `attachBaseContext`, then `recreate()`. Also set `AppSettings.localeTag`. The footer is the privacy promise from screen 01 ("No account · Works offline · Your data stays on your phone"), and it links to a Privacy sheet. Strings fall back to English until M16. Add `androidResources.generateLocaleConfig = true` and `res/resources.properties` with `unqualifiedResLocale=en`.
  2. **City.** Search after 2 or more characters, debounced 150 ms, `limit = 20`, on IO. Pick a hit to create `SavedPlace(newRecordId, place, pinned = true, now)` and set `homePlaceId`. "Use approximate location": show an in-context rationale dialog first, then request `ACCESS_COARSE_LOCATION`. Use `LocationManager.getCurrentLocation(NETWORK_PROVIDER)` on API 30+ and `requestSingleUpdate` below 30, with a 10 s timeout, then `nearest(lat, lon, 100.0)`. Discard the coordinates right after; only the GeoPlace is stored. If the user denies, the request times out or nothing matches, stay on search with a non-alarming message. Continue is disabled until a place is chosen.
  3. **Tradition.** North (purnimanta) → PURNIMANTA; South/West (amanta) → AMANTA; Not sure → `RegionPresets.forPlace(place)`. That table is empty in M07 (**VERIFY, TODO(owner)**), so it falls back to AMANTA with `presetSource = NOT_SURE_DEFAULT`, and Conventions shows "Default, change anytime". No regional presets in M07.
  4. **Birth details** (optional, Skip). Date (M3 DatePicker), time or "I don't know the time" → `BirthData(date, null, false)`, and a place from the same search. Compute the offset with `OffsetResolver.localToInstant`. If `alternative != null`, ask Earlier/Later; if the result is flagged uncertain, offer `OffsetPickerModel` (core:geo, used as-is) for a manual offset. Save `Profile(relation = SELF, origin = OWN, displayName = R.string.profile_me, calc = settings.defaultCalc)` and set `selfProfileId`.
  5. **Reminders** (optional). Four `ReminderKind` toggles, all off by default. On Continue, if any toggle is on and API ≥ 33 and permission is not yet granted, request `POST_NOTIFICATIONS`. If the user denies, keep the preferences and show "You can turn this on in Settings". M07 posts nothing.
  - Finish writes `onboardingDone = true` and routes to `Root(AAJ)`. Every step persists its choice when the user continues, and the machine state survives `recreate()` (activity-scoped ViewModel). Back returns to the previous step. Skip exists only on steps 4 and 5.
- **Settings** (opened from the avatar): Appearance (theme mode; dynamic colour, shown only on API 31+; Bada Text; reduce motion), Language (the step 1 list), Conventions, Privacy (a static promise screen). **Conventions (J4):** `AyanamsaId.entries`, `SunriseConvention.entries`, MonthSystem, `DashaYear.entries`, Ekadashi `Tradition` (SMARTA/VAISHNAVA), ChartStyle. Each option has a label and a one-line explanation as strings, and each change writes `settings.defaultCalc` or the AppSettings field. Existing profiles keep their own `calc`.
- **Search palette:** opened from the top-bar search icon as a full-screen dialog. Entries cover the 5 tabs, Settings, Conventions and Privacy. Labels are the localized string plus an untranslatable English alias `string-array`. Matching: NFC, case-fold, trim; rank 0 for a label prefix, 1 for a word prefix, 2 for a substring; ties go by entry order.
- **Placeholders:** each tab root shows `PpTopBar` (title = tab label, subtitle = the home place name) and an `EmptyState` ("Coming soon" plus one line). There is no sample or fake data.
- **Splash:** `values-v31/themes.xml` sets `windowSplashScreenBackground` (ivory, night variant indigo) and `windowSplashScreenAnimatedIcon` = `@drawable/pp_brand_mark` (an original diya in a rounded square). Below 31, `windowBackground` is a layer-list with the same mark. Switch to the app theme in `onCreate`. No ad.
- **Icons:** original, simple geometric vectors in `core/designsystem/src/main/res/drawable/`: `ic_tab_aaj` (sun), `ic_tab_calendar`, `ic_tab_kundli` (planet with ring), `ic_tab_bonds` (two linked circles), `ic_tab_bhakti` (diya), `ic_search`, `ic_settings`, `ic_location`, `pp_brand_mark`. Every icon has a `contentDescription` string, or null when it is decorative next to a label.
- **Accessibility:** use start/end only, never left/right (RTL-safe), and mirror directional icons with `autoMirrored`. Selected tabs show `stateDescription`. Group cards with `semantics(mergeDescendants = true)`. Every interactive element is at least 48 dp.
